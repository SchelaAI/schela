## Required end-to-end launch test

Run this exact path with a real test phone and real test email:

```text
Recruiter signup
→ onboarding
→ add interviewer
→ connect Calendly
→ choose event type
→ add candidate
→ create WhatsApp interview
→ receive WhatsApp template
→ candidate replies
→ Schela AI replies
→ candidate asks to schedule
→ Schela sends single-use Calendly link
→ candidate books
→ Calendly webhook confirms interview
→ candidate receives confirmation
→ verify Schela inbox contains the entire conversation
→ verify dashboard/interview state
→ trigger/test reminders in staging
```

Then run the fallback path separately:

```text
Create WhatsApp interview
→ do not reply
→ make test row eligible for fallback in staging
→ POST cron endpoint
→ exactly one Resend email is sent
→ candidate replies by email
→ reply appears in same Schela conversation
→ Schela replies by email
```

## Release decision

- **GO:** every P0 passes, build passes, fresh migrations pass, and real provider end-to-end test passes.
- **NO-GO:** any P0 failure, any cross-tenant access, duplicate external messages, invalid webhook accepted, build/migration failure, or provider secret exposed to client output.
